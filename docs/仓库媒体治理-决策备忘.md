# 决策备忘 · 仓库媒体治理（2026-09-30 初稿 · 2026-10-04 实证更新）

> 状态：**实证已完成，待拍板**。本文不改动任何历史，不做 force push。

## 问题

- `.git` 已 **1.9GB**：`movies/` 下 951 部影片的 cover.jpg（≥780 宽）与 still.jpg（≥1920 宽）全部进了 git 历史，`assets/posters`、`assets/stills` 另有 ~270MB。
- 纯静态站无 CI 构建 CDN，GitHub Pages 直接服务这些图片；Pages 单文件 100MB 上限未触碰，但仓库整体体积已远超 GitHub 的建议值（<1GB），clone/fork 体验差。
- 每扩一批（C30 ×14 ≈ +100MB，冲 2000 部 ≈ 再 +1GB+），历史只增不减。**越晚治理，重写成本越大。**

## 选项

| 方案 | 做法 | 优点 | 代价 / 风险 |
|------|------|------|------|
| 0 · 维持现状 | 不动 | 0 成本 | 仓库持续膨胀；GitHub 对 >5GB 仓库有硬限制，按当前增速一年内逼近 |
| 1 · Git LFS（推荐） | `git lfs migrate import --include="movies/*/cover.jpg,movies/*/still.jpg,assets/posters/**,assets/stills/**" --everything` | 引用路径不变、前端零改动；Pages 对 LFS 媒体直接可用（带宽走 LFS 配额） | 需要 force push 重写历史；LFS 免费配额 1GB 存储 / 1GB 月带宽，超出需付费（当前媒体 ~2GB，必超带宽配额） |
| 2 · 媒体出仓 | 媒体迁到独立私有仓/R2/OSS，仓库只留 meta.json + 相对路径约定；Pages 加一层 CDN 或自定域名指向媒体源 | 主仓瘦身到 <100MB；扩库只动媒体仓 | 构建链路要改（build 需校验媒体仓存在）；外部依赖多一个 |
| 3 · 历史瘦身不迁移 | `git filter-repo` 把历史里的大图压缩/丢弃，当前版本保留 | 主仓变小且无新依赖 | 损失历史版本图；仍会随扩库再涨，治标 |

## 事实核查（2026-10-04 用一次性测试仓 shenlq1017/silver-lfs-pages-test 实测）

- **branch 部署（Pages 传统方式）遇到 LFS 会翻车**：Pages 直接服务的是 LFS **指针文件**（128 字节文本），浏览器拿到的是坏图。初稿「Pages 可以直接服务 LFS 媒体」的说法**是错的**。
- **Actions 部署可正常服务真实媒体**：workflow 里 `actions/checkout@v4` 需显式 `lfs: true`（先跑 `git lfs pull` 再传 artifact），实测 JPEG magic bytes（ff d8）正常返回。前提是切到 **Settings → Pages → Build and deployment → Source: GitHub Actions**。
- **配额账**：LFS 免费层 = 1 GiB 存储 + 1 GiB/月带宽。本仓媒体 ~1.87GB，**免费存储第一天就不够**——选 LFS 就必须买 $5/月 data pack（50GB 带宽 + 计费存储），不是"超了再买"。
- LFS 数据不进 `git clone` 主包，浅层体验立即改善（主仓只剩指针）。
- 测试仓 `silver-lfs-pages-test` 遗留未删（gh 缺 `delete_repo` scope），需手动在 GitHub 上删除。

## 建议（按实证修订）

- **方案 1（LFS）成立的完整前提 = ① workflow 部署 + ② $5/月 data pack**。两者缺一 Pages 上就是坏图/超配额。执行顺序：
  1. `git lfs install` → `git lfs migrate import --everything --include="*.jpg"`（先 `git lfs migrate info` 评估）
  2. 新增/改造 Pages workflow：checkout `lfs: true` + `upload-pages-artifact` + `deploy-pages`，并切换 Pages Source 为 GitHub Actions
  3. 购买 data pack（$5/月）
  4. 本地全量校验（build 幂等 + 三页冒烟 + `git lfs fsck`）→ PM 终验后 force push（**唯一需要 force push 的一步，须明确授权**）
- **若不愿付 LFS 月费 → 方案 2（媒体出仓）**：Cloudflare R2 免费 10GB 存储 + 无流量费，仓库路径约定不变，build 需校验媒体源存在。以本仓体量（1.87GB，还在涨），**R2 路线的总成本更低，推荐优先评估**。
