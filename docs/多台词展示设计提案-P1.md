# 多台词前端展示设计提案（ROADMAP Part 1 · P1）

> 状态：**方案 A 已定稿并实施（2026-09-26）**。quotes.json 增加 `extra_count`；build 生成 `data/lines/{id}.json`；列表卡片「本片还有 N 句」、详情页「本片台词」区块 + 逐句复制已上线（本地冒烟通过）。
> 前置：台词深挖储备进行中（`data/dig-batches/batch-*.draft.json` → `movies/{id}/meta.json` lines[]，现阶段不上架）。

## 现状

- `scripts/build.mjs` 只把**主台词**（featured 或 lines[0]）展开进 `data/quotes.json`；储备台词留在 `movies/{id}/meta.json` 的 `lines[]`（构建时仅提示条数）。
- 列表卡片 `cardHtml()`、详情页 `renderDetail()` 均单条；详情页为 `quotes/{id}/` 壳页 + 静帧一屏。
- `data/quotes.json` 当前 ~1.5MB / 951 条，前端单次 fetch。

## 方案对比（数据分发层）

| 方案 | 做法 | 优点 | 代价 |
|------|------|------|------|
| **A（推荐）** | `quotes.json` 每条只加 `extra_count` 字段；储备句由 build 生成 `data/lines/{id}.json`（每片一个，含全量 lines），详情页按需 fetch | 列表页零增重；详情页一个轻量请求；源与分发解耦 | 详情页多一次请求（几十 KB，可接受） |
| B | 储备句全量并入 `quotes.json` | 实现最简单；今日一句句子级零成本 | 文件 +~1MB（2000+ 句），列表页付出全部重量 |
| C | 前端直接 fetch `movies/{id}/meta.json` | 零生成物 | 暴露 `license_note` 等策展源字段；字段冗余；不推荐 |

> 远期触发器：`quotes.json` 超过 ~3MB 或列表加载可感知变慢时，再按分组拆 `quotes-top250.json` / `quotes-classics.json` + 轻量索引文件（`data/index.json`：分组计数与 id 清单），前端按 tab 懒加载。源数据（movies/）不用动——quotes.json 本就是 build 生成物，分发形态随时可重排。

## UI 设计（书卷风，浅色）

1. **片语集卡片**：主台词展示不变；卡片元信息行末尾追加灰色小字「本片还有 N 句」（N=0 不显示）。点击仍进详情页。
2. **详情页**：静帧一屏（主台词）完全不动；静帧下方新增「本片台词 · 共 N 句」区块：
   - 逐条列出储备句：中文 text 为主（稍小于主台词字号），en 原文以次级色/较小字号随行，说话人角色右对齐小字；
   - `note`（语境/核证线索）以更浅色小字附于句下；
   - 每句支持点击复制；不设收藏按钮（句子级收藏放后续版本，key 约定 `${id}#${index}`）。
3. **今日一句 / 随机**：P1 暂不改（仍影片级）。句子级抽取放 P1.5：届时 build 额外产出轻量 `data/all-lines.json`（`{id, text, character}[]`，预计 300~500KB）供随机/今日一句按句抽取。

## 改动清单（定稿后执行）

- `scripts/build.mjs`：`expand()` 增加 `extra_count`；新增 `data/lines/{id}.json` 生成（方案 A）
- `assets/js/site.js`：`cardHtml()` 加「还有 N 句」标记；`renderDetail()` 加台词区块 + 复制交互
- `assets/css/style.css`：台词区块样式（次级字号、分隔线、复制反馈）
- `scripts/sync-quote-pages.mjs`：无改动（壳页不变）
- 门禁新增：`extra_count === lines.length - 1`；featured=5 与文案边界不变

## 验收

- 卡片可见「本片还有 N 句」，详情页可见全部台词与 note；
- `quotes.json` 体积增幅 <5%（方案 A）；
- 本地 HTTP 冒烟：首页 / 片语集 / 详情 / 收藏 / 随机无回归；旧链接 `quotes/{id}/` 全部可用。
