## 开关位置（与信息图标关系）

现有右上角已有 **信息图标**（`.detail-info-anchor`）。音乐开关与之组成 **同一角落工具簇**，避免第二套角落逻辑。

```
                    顶栏
         ······························
                              ┌────┐ ┌────┐
                              │ ♪  │ │ ℹ  │   ← 右上工具簇
                              └────┘ └────┘
                               音乐    信息
```

| 规则 | 建议 |
|------|------|
| 位置 | **信息图标左侧**（音乐在左、信息在右）；间距 10–12px |
| 共同边距 | `top: 72–88px`，`right: 28–36px`（与信息方案一致） |
| 尺寸 | 与信息钮同规格：热区 ≥44×44，图形 20–24px，半透明圆底 |
| 层级 | 与信息钮同层，均压在 still 之上、低于顶栏可点区域之下即可 |
| 互不抢 | 打开信息悬浮框时，**音乐钮保持可见可点**；不要把音乐塞进信息框里（信息框是影片元数据，音乐是环境控制） |

**不推荐：** 把开关放进信息悬浮框底部（多一步、默认态找不到）；不推荐左下（易碰金句区）；不推荐顶栏导航里（详情沉浸感被打断）。

## 图标与状态

| 状态 | 视觉 | `aria-label` 示例 |
|------|------|-------------------|
| 静音 / 未播 | 喇叭斜杠 或 音符+斜杠 | 「打开背景音乐」 |
| 播放中 | 喇叭 / 音符实心，可极轻脉冲（opacity 呼吸，勿大红点） | 「关闭背景音乐」 |
| 无可用音频 | 按钮 `disabled` 或隐藏整钮 | — |

用 SVG，不用 emoji。激活描边可走金色 accent，与信息钮 hover 一致。

## 交互节奏（手势与默认）

1. **进页：** 音频元素可 `preload="metadata"`；**不自动出声**。UI 为静音态（即使用户拍板「希望有音乐」，也须等手势）。
2. **首次打开音乐：** 用户点击音乐钮 → `audio.play()`；成功后切到播放态。若浏览器拒绝，保持静音态并可选 `title` 提示「请再点一次」。
3. **再次点击：** pause + 静音态；记住本会话偏好可用 `sessionStorage`（可选，拍板后定）。
4. **切详情 / 回列表：** `pause()` 并复位，避免后台声；若拍板「站内连续垫乐」再另开需求（本阶段不做）。
5. **与信息框：** 互不影响；点空白关闭信息框时**不要**误关音乐。
6. **一屏门禁：** 不因音乐增加任何需滚动的 UI；无歌词面板、无播放列表抽屉。

## 做什么 / 不做什么

### 做（可落地）

- 右上 **音乐 | 信息** 双钮（音乐左、信息右）
- `assets/audio/` 放入 1 条可商用氛围 loop + 授权说明（about 或 data）
- 默认静音；点击 unmute+loop；session 可记；切页暂停

### 不做

- 不写入 / 不引用未授权电影原声
- 不破坏全屏 still、金句叠字、一屏无滚条
- 不把播放器做成大控件或第二屏
- 不代写本轮前端业务逻辑以外的「曲目选型」
- 不把电影 OST 写进仓库；不做按条原声字段
